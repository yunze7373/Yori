## 2. Slice D1 — weather follows the consented fix (P0, ~4h)

Verified gap: `OpenMeteoWeatherAdapter` is hardwired to `DEFAULT_DEMO_CITY` and the proxy resolves coords from `DEMO_CITY_*` env only — no path exists for a device fix to reach the query. Design: `/api/weather/current` accepts optional `coords=lat,lng` (strict numeric validation, first-party proxy only); the client sends the consented fix rounded to 3 decimals (~100 m, privacy by rounding); the proxy builds the adapter with those coords and the response carries coordinate provenance (rounded fix plus `fetchedAt`); without fix or consent Live shows honest unavailable — demo-city fallback is forbidden in Live and stays only behind `?dev=1` and recorded tests. Server never logs coordinates. Acceptance: grant flow on owner device shows owner-city weather with source plus time; deny flow shows the guided card; proxy tests prove no coords in logs and no unrounded fix on the wire. Non-goals: forecast windows (see note), unit changes.
